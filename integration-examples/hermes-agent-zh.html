03 / 为什么用 HOLOGROW

持续运行的 Agent，需要持续维护的经营依据。

一条建议被反复输出，而缺失输入从不出现在简报里，团队就更容易把它当成事实。

当数据彼此割裂

  1. 01只看销售的流程，可能反复建议放量，却从未核对花费。
  2. 02输入过期，定期生成的简报却看起来像最新判断。
  3. 03商品映射改变，下一次比较的范围也悄悄变了。

通过 HOLOGROW

  • 通过同一托管 MCP 连接，读取已同步电商与营销记录。
  • 将来源覆盖与同步检查设为流程的必要输入。
  • 采用可查业务键与维护好的手工背景表，运行前验证映射。

05 / 试着这样问

给 Hermes Agent 的三个起始问题。

复制问题，补充账户、站点与报告日期。每个问题都需要相关数据源已经可用。

01

编写复盘流程

为 Hologrow 数据编写只读 Hermes 经营复盘流程，定义必要输入、证据检查、停止条件与简报格式。

02

排查渠道变化

比较完整周的可用店铺销售与广告花费，识别渠道结构变化，并列出调整分配前还需要的证据。

03

复核上一次简报

结合可用 Hologrow Schema 与报告日期复核这份经营简报，标记缺乏依据的结论、含义模糊的指标及应重做的检查。

06 / 安全与控制

Hermes Agent 只读数据，控制权在你手中。

授权数据连接，账户操作仍由你决定。

连接凭据加密保存

Hologrow 加密保存源连接凭据，AI 访问范围跟随授权连接的 Hologrow 用户。

源数据访问保持只读

通过 Hologrow 分析已同步记录，不修改出价、预算、商品或订单。执行前请复核 AI 结论。

随时撤销访问

在 AI Platforms 轮换或撤销 MCP key，不要将 key 写入报告或共享项目文件。

AI 客户端与模型提供方有各自的权限和数据政策。Hologrow 的只读边界适用于其提供的工具。

Hologrow 会托管我的 Hermes Agent 吗？

不会。Hologrow 托管已同步的数据服务，你负责安装与运行 Hermes、配置模型提供方，以及决定如何触发工作流。

Hermes 如何向 Hologrow 授权？

文档流程使用 MCP key，通过 Streamable HTTP 发送 Bearer 授权 header。请采用 Hermes 原生 MCP 配置和指南中的安装提示词。

自托管 Agent 是否意味着请求都留在我的电脑上？

不一定。Hermes 可能调用所配置的模型提供方，Hologrow 也是远程数据服务。使用敏感经营背景前，应了解各服务的数据处理方式与配置。

可以定期执行 Hermes 复盘吗？

定期执行依赖你为 Hermes 提供的调度与运行配置。Hologrow 提供已同步数据，但连接本身不会启动 Agent 或投递报告。

可以加入内部目标或商品映射吗？

Hologrow 支持手动数据表，用于维护业务背景。应定义稳定的键、负责人和更新流程，Agent 比较前仍需验证映射。

Agent 应如何处理不完整的数据？

流程应明确哪些输入缺失时必须停止比较，哪些只影响结论范围。要求 Agent 报告缺口，避免编造数值或给出过度确定的解释。

Hermes 能通过 Hologrow 操作源账户吗？

Hologrow MCP 为只读。它支持调查和简报，但这条连接不负责修改广告、订单、价格或库存。
