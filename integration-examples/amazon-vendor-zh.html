02 / MCP

让 AI 调用数据工具

MCP 规定客户端如何发现和调用工具。实际覆盖、更新速度和是否保存历史，取决于工具背后的服务实现。

03 / HOLOGROW

持续准备回答背后的依据

Hologrow 拉取可用 Amazon Vendor 数据，整理字段与业务键，维护定期同步，再通过只读 MCP 提供可检查的数据表。加入其他已连接来源时，保留各自的口径和覆盖范围。

这是相互配合的不同层次。其他来源 MCP 也可能提供额外服务，应比较其具体实现。Hologrow 不绕过源端权限，也不会让不同指标自动变成同一口径。

FAQ

Amazon Vendor MCP 集成常见问题

Vendor 和 Seller 数据一样吗？

不一样。Vendor 是包含采购订单和专用报表的 1P 供货业务；Seller 的消费者订单与结算分析使用另一种连接。

可以把 Vendor 与 Sponsored 广告一起分析吗？

两端已连接且报告可用时可以并列分析。比较前需核对商品对应、站点、日期与广告归因口径。

AI 可以使用哪些 Amazon Vendor 报告？

公开目录包含采购订单及明细、发货、销售、流量、库存、目录和 Listing、利润相关报告与预测。可用性因 Vendor 账户而异，每个指标都应保留源报告定义。

Vendor MCP 能将采购订单与零售销售对账吗？

可以在同一次复盘中查看两类数据，但它们分别描述 Amazon 采购和终端客户销售。比较时对应商品与周期，不应强行要求两个总数一致。

连接 Vendor Central 后可以取得全部 SP-API 报告吗？

不能。Hologrow 同步受支持且账户有权访问的报告。授权不会额外授予 Amazon 权益，也不会补出不存在的历史，需在工作区核实表与日期。

Amazon Vendor API 与 MCP 连接有什么区别？

API 向程序提供 Amazon Vendor 的资源与报表；MCP 让 AI 客户端发现并调用工具，这些工具可以直接查询 API，也可以查询已存储的数据层。MCP 协议本身不保证定期同步、历史保留或跨源映射。Hologrow 负责连接来源、维护可用的同步表，再通过托管 MCP 提供只读工具。

为什么用 Hologrow，而不是自己接 Amazon Vendor API？

有能力维护授权和请求逻辑时，直接调用 API 可以满足单次、明确的查询。持续复盘 Amazon Vendor 还需要拉取、存储、更新、可用历史和明确字段定义。Hologrow 维护这层数据准备工作，并让表级覆盖可检查，使 AI 能沿已有依据继续追问、加入其他已连接来源。价值在持续维护的数据层，不是声称 API 数据更不准确。

Hologrow MCP 提供实时 Amazon Vendor 数据或无限历史吗？

不提供这样的保证。AI 查询已经同步到 Hologrow 的数据；刷新计划与可回填历史因来源和数据表而异。请在 Data Explorer 检查最近成功同步和覆盖日期。MCP 端点已连接，不会消除源 API 权限、报表延迟或历史窗口限制。

如何将 Amazon Vendor 连接到 Claude、ChatGPT 或 Codex？

先在 Hologrow 授权 Amazon Vendor，到 Data Explorer 核对可用表和日期，再按所选 AI 客户端指南添加 Hologrow。AI 通过托管 MCP 连接查询已同步数据。
