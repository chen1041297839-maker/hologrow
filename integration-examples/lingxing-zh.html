02 / MCP

让 AI 调用数据工具

MCP 规定客户端如何发现和调用工具。实际覆盖、更新速度和是否保存历史，取决于工具背后的服务实现。

03 / HOLOGROW

持续准备回答背后的依据

Hologrow 拉取可用 Lingxing ERP 数据，整理字段与业务键，维护定期同步，再通过只读 MCP 提供可检查的数据表。加入其他已连接来源时，保留各自的口径和覆盖范围。

这是相互配合的不同层次。其他来源 MCP 也可能提供额外服务，应比较其具体实现。Hologrow 不绕过源端权限，也不会让不同指标自动变成同一口径。

FAQ

Lingxing ERP MCP 集成常见问题

Hologrow 会替代领星 ERP 吗？

不会。领星继续承担业务系统角色，Hologrow 将可用且已同步的 ERP 背景与其他来源一起提供给 AI 做只读分析。

AI 能判断冲突数字哪一个正确吗？

可以检查可用定义、日期和记录，指出差异所在。缺失明细必须保留为缺口，语气肯定的回答不能替代对账。

通过 MCP 可以把哪些领星 ERP 数据带进 AI？

产品目录展示 59 张领星表，本页精选 13 张，包括组合商品、汇率、FBA 入库货件、财务费用明细、头程物流对账、关键词监控和 Listing 关联关系。具体字段与日期范围可在工作区核对。

Hologrow 与只连接一个 ERP MCP 有什么区别？

ERP MCP 提供什么工具，取决于其服务方实现。Hologrow 的重点是让可用 ERP 背景与独立连接的广告、电商及分析数据一起可查询，并能检查 Schema 与覆盖。应比较实际工具和表支持，而不只看 MCP 名称。

领星与 Amazon 数字冲突时如何排查？

先对齐店铺、站点、业务日期、币种和订单状态，再检查 SKU 对应和可用明细，最后展示剩余差额。Hologrow 不会悄悄指定某一端一定正确，也不会覆盖源记录。

Lingxing ERP API 与 MCP 连接有什么区别？

API 向程序提供 Lingxing ERP 的资源与报表；MCP 让 AI 客户端发现并调用工具，这些工具可以直接查询 API，也可以查询已存储的数据层。MCP 协议本身不保证定期同步、历史保留或跨源映射。Hologrow 负责连接来源、维护可用的同步表，再通过托管 MCP 提供只读工具。

为什么用 Hologrow，而不是自己接 Lingxing ERP API？

有能力维护授权和请求逻辑时，直接调用 API 可以满足单次、明确的查询。持续复盘 Lingxing ERP 还需要拉取、存储、更新、可用历史和明确字段定义。Hologrow 维护这层数据准备工作，并让表级覆盖可检查，使 AI 能沿已有依据继续追问、加入其他已连接来源。价值在持续维护的数据层，不是声称 API 数据更不准确。

Hologrow MCP 提供实时 Lingxing ERP 数据或无限历史吗？

不提供这样的保证。AI 查询已经同步到 Hologrow 的数据；刷新计划与可回填历史因来源和数据表而异。请在 Data Explorer 检查最近成功同步和覆盖日期。MCP 端点已连接，不会消除源 API 权限、报表延迟或历史窗口限制。

如何将 Lingxing ERP 连接到 Claude、ChatGPT 或 Codex？

先在 Hologrow 授权 Lingxing ERP，到 Data Explorer 核对可用表和日期，再按所选 AI 客户端指南添加 Hologrow。AI 通过托管 MCP 连接查询已同步数据。
